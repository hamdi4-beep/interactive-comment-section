I'll be going over how the comment section works so I can figure out the number of assumptions I'm making to ensure it works reliably in different scenarios.

First, it loads data from a json file that needs to be in a specific format. This means I have to validate its shape against a schema to make sure the data is only rendered when it's valid.

CommentsList.tsx:

The 'CommentsList' component grabs a list of comments by their ids where each 'Comment' component receives an 'id' prop that is used to select the comment object represented by the said 'id' property.

Comment.tsx:

The 'Comment' component is where the handlers that dispatch an action are defined. This is where they have access to the comment's id property. It renders both the 'Card' and 'Reply' components, but it checks to see whether the replies exist first before it renders the component. This means it doesn't make the assumption that a reply object with an ID exists.

Reply.tsx:

The 'Reply' component is pretty similar to the 'Comment' component in that the handlers are also defined here where they have access to both the 'id' property and that of the parent comment.

Card.tsx:

The 'Card' component is only responsible for the structure and visual of a comment/reply card. It isn't responsible for how any of them work or the way they behave. It makes the assumption that whether you pass in the comment or reply object then the data is already in the expected format. Only common behavior that's necessary for both a comment and reply is defined here.
